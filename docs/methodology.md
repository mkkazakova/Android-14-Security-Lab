# Протокол исследования

Планируемые реакции ниже не являются фактическими результатами. Результаты и изображения формируются отдельно для каждого запуска.

## 01. Direct Boot и доступность DE/CE

**Цель.** Проверить доступ к двум существующим записям до и после первой разблокировки Android.

**Действия.** Создать случайные записи DE и CE, сохранить SHA-256. Настроить PIN, выполнить adb reboot. В directBootAware BroadcastReceiver прочитать оба файла на LOCKED_BOOT_COMPLETED. Ввести PIN через системный интерфейс, повторить чтение и сравнить хеши. После обычной блокировки проверить состояние пользователя.

**Критерий.** До первого PIN: isUserUnlocked=false, DE читается, CE возвращает исключение. После PIN обе исходные записи читаются. Обычная блокировка не отменяет первую разблокировку.

**Ограничения.** Проверяется жизненный цикл доступа DE/CE на образе с ro.crypto.type=file. Не измеряется криптостойкость FBE, защита от извлечения диска или аппаратная привязка ключей. Снимок экрана блокировки сам по себе не доказывает отказ CE.

Исполнение: `scripts/run.py`, метод `direct_boot`. Фактические события и журналы находятся в папке этого опыта в артефакте.

## 02. Android Keystore и системный PIN

**Цель.** Проверить обязательность действующей аутентификации для настоящего AES/GCM.

**Действия.** Создать AES-ключ AndroidKeyStore с AUTH_DEVICE_CREDENTIAL и окном 30 секунд. Подтвердить PIN в системном окне, зашифровать случайную запись и расшифровать её. Выждать 35 секунд, повторить Cipher.init/расшифрование без новой аутентификации. Снова подтвердить PIN и открыть тот же шифротекст.

**Критерий.** С действующей аутентификацией расшифрованные байты совпадают с исходными. После тайм-аута получен UserNotAuthenticatedException. Новый PIN восстанавливает доступ к тому же шифротексту.

**Ограничения.** Это временное окно доступа, а не запрос PIN перед каждым doFinal. PIN вводится в системный интерфейс; приложение его не читает. Уровень KeyInfo.securityLevel фиксируется, но эмулятор не доказывает аппаратную безопасность физического TEE/StrongBox. Тестовые записи и результаты расшифрования публикуются в журнале.

Исполнение: `scripts/run.py`, метод `keystore`. Фактические события и журналы находятся в папке этого опыта в артефакте.

## 03. Подпись APK при обновлении

**Цель.** Проверить, может ли APK с независимой подписью заменить установленное приложение.

**Действия.** Установить Update Sample v1, подписанный A, и создать запись. Установить через adb install -r версию 2 с тем же packageName, но подписью B. Проверить отказ, версию и запись. Затем установить версию 2 с подписью A и проверить сохранение записи.

**Критерий.** Package Manager возвращает INSTALL_FAILED_UPDATE_INCOMPATIBLE для B; версия 1 остаётся. Обновление A проходит, версия становится 2, хеш записи сохраняется.

**Ограничения.** Установка через ADB не показывает системный диалог ошибки; главное доказательство — ответ Package Manager и отпечатки подписей. Опыт не оценивает добросовестность автора, отзыв сертификатов и ротацию signing lineage.

Исполнение: `scripts/run.py`, метод `apk_signature`. Фактические события и журналы находятся в папке этого опыта в артефакте.

## 04. Недоверенные касания и скрытие overlay

**Цель.** Проверить системную фильтрацию касаний через окно другого UID и API скрытия overlay.

**Действия.** Сохранить запись обычным касанием. Lab Helper создаёт два перекрывающихся TYPE_APPLICATION_OVERLAY другого UID с FLAG_NOT_TOUCHABLE, alpha=0.65 каждое (суммарная непрозрачность 0.8775 > порога 0.8). Повторить касание в той же точке; сопоставить счётчики доставки событий и запись InputDispatcher. Включить setHideOverlayWindows(true), повторить касание. Отключить скрытие и убедиться, что окно Helper снова видно без перезапуска.

**Критерий.** Обычное касание доставляется; под непрозрачным чужим окном событие не приходит, InputDispatcher указывает occlusion. После скрытия overlay та же кнопка работает.

**Ограничения.** Разрешение наложения — подготовка через appops, а не предмет опыта. Лаборатория не отключает block_untrusted_touches. Не исследуются прозрачные, частичные, доверенные системные наложения и все возможные варианты tapjacking. Без журнала причины результат INCONCLUSIVE.

Исполнение: `scripts/run.py`, метод `tapjacking`. Фактические события и журналы находятся в папке этого опыта в артефакте.

## 05. TLS и Network Security Configuration

**Цель.** Раздельно проверить цепочку доверия, имя сервера и политику открытого HTTP.

**Действия.** Запустить на runner локальные серверы с одноразовыми сертификатами. Через HttpsURLConnection запросить доверенный сертификат с SAN IP 10.0.2.2, сертификат чужого CA и сертификат доверенного CA с чужим DNS-именем. Запросить HTTP на запрещённом 10.0.2.2. Через adb reverse запросить тот же HTTP-сервер на разрешённом localhost. Проверить nonce текущего сервера.

**Критерий.** Доверенный TLS возвращает текущий nonce; чужой CA вызывает SSLHandshakeException с причиной проверки цепочки; чужое имя — SSLPeerUnverifiedException; запрещённый HTTP отклоняется cleartext policy; разрешённый контроль возвращает nonce.

**Ограничения.** CA доверен только этому лабораторному APK для указанного хоста. Системное хранилище сертификатов не изменяется. NSC не является системным межсетевым экраном для любых нативных сокетов. Ни внешние сайты, ни отключение проверки TLS не используются.

Исполнение: `scripts/run.py`, метод `tls`. Фактические события и журналы находятся в папке этого опыта в артефакте.

## 06. MediaProjection, FLAG_SECURE и повторное согласие

**Цель.** Проверить согласие на реальный захват, исключение защищённого окна и одноразовость MediaProjection для createVirtualDisplay.

**Действия.** Lab Helper вызывает системное согласие на захват всего дисплея. После согласия foreground service создаёт MediaProjection, callback, ImageReader и VirtualDisplay. Сохранить кадры обычного окна, того же окна с FLAG_SECURE и после снятия флага. На исходном MediaProjection повторно вызвать createVirtualDisplay.

**Критерий.** Обычный и восстановленный кадры содержат цветной маркер. Защищённый кадр не содержит маркер. Повторный createVirtualDisplay возвращает SecurityException при targetSdk=34.

**Ограничения.** Кадры берутся из ImageReader, не подменяются скриншотами ADB. FLAG_SECURE не защищает от внешней камеры или привилегированной модификации ОС. Проверяется повторное создание VirtualDisplay на одном объекте, а не все варианты повторного использования Intent согласия.

Исполнение: `scripts/run.py`, метод `media_projection`. Фактические события и журналы находятся в папке этого опыта в артефакте.
