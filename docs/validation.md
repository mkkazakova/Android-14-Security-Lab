## Что проверено фактически

- Подготовка одноразовых TLS-сертификатов и двух независимых подписантов APK.
- Компиляция Kotlin и сборка всех трёх приложений через Gradle 8.13, AGP 8.13.2, Kotlin 2.3.20, Java 17, Android SDK 34 / Build Tools 35.0.0.
- Полный `scripts/build.sh`: созданы пять APK, включая версии 1-A, 2-A, 2-B Update Sample. После последних изменений интерфейса/NSC Security Lab и Helper пересобраны.
- Повторная сборка из ZIP, распакованного в новую папку без `.gradle`, `build`, `.lab-secrets` и `results`: `scripts/build.sh` создал все пять APK и успешно проверил подписи/манифесты. Использовались только установленные SDK/JDK и общий кэш скачанных зависимостей.
- `apksigner verify --verbose --print-certs` для всех пяти APK. По выводу SDK `aapt` проверены packageName, minSdk/targetSdk 34, versionCode; подписи 1-A и 2-A совпадают, 2-B отличается.
- Android Lint для `lab`, `helper`, `sample`: **ошибок нет**. Предупреждения не скрыты; полный вывод приложен.
- **13 host-тестов**, включая реальные TLS-handshake на локальном сервере, неверный CA/имя; обработку отсутствующих результатов, старого коммита/запуска, повреждённого изображения; разделение ERROR/FAIL/INCONCLUSIVE и продолжение независимых сценариев. Тесты выполнены в отдельном Python-окружении с точными версиями `scripts/requirements.txt`.
- Workflow проверен `actionlint 1.7.7`; параметры emulator-runner сопоставлены с опубликованным `action.yml`.
- Python: синтаксис/импорт; Bash: `bash -n`; Android XML: синтаксический разбор; Gradle Wrapper: целостность JAR. Для Gradle distribution задан официальный SHA-256.
- HTML/JSON/JUnit: проверена генерация при отсутствии результатов; шесть опытов остаются NOT_RUN, в JUnit записываются skipped, изображения не выдумываются. Проверены экранирование текста и контроль хешей PNG.

Журналы этих проверок: [validation/](validation/). Это журналы **проверки поставки**, не доказательства работы Android. Синтетические объекты в unit-тестах используются только для проверки обработчика результатов и никогда не добавляются в отчёты экспериментов.

## Что ещё не проверено

В среде подготовки нет `/dev/kvm`. Android Emulator и шесть опытов **не запускались**. Соответственно, здесь нет подтверждённых результатов Android и доказательных снимков из AVD. Основной критерий приёмки — шесть реальных опытов с проверяемыми доказательствами — предстоит подтвердить первым запуском GitHub Actions.

В исходниках реализованы все шесть сценариев, а не заглушки, но следующие места требуют проверки на фактическом образе Google APIs API 34:

1. Доставка LOCKED_BOOT_COMPLETED, реальная недоступность CE и разблокировка PIN после reboot.
2. Системное окно подтверждения PIN, ввод через UI Automator/ADB и тайм-аут аутентификации Keystore.
3. Формат диагностической записи InputDispatcher для blocked untrusted touch.
4. Диалог согласия MediaProjection, получение свежего кадра защищённого экрана и исключение второго createVirtualDisplay.
5. Полный сетевой маршрут host ↔ emulator, точные исключения Android TLS/HTTP.
6. Фактический отказ Package Manager на несовместимую подпись и сохранение данных при обновлении.

Если нужный API/элемент UI/журнал отсутствует, сценарий выдаёт ERROR либо INCONCLUSIVE и сохраняет диагностику. Отсутствие реакции не подменяется заранее заданным PASS. Исправления после первого CI-запуска могут потребоваться; успешную работу на AVD заранее не заявляем.

## Оставшиеся предупреждения Lint

- `OldTargetApi`/`GradleDependency`: API 34 выбран намеренно для фиксированной платформы опыта.
- `ApplySharedPref`: синхронная запись нужна перед reboot/обновлением; объём записей мал.
- `SetTextI18n`: интерфейс рассчитан на русский язык, строки учебного приложения заданы непосредственно в Kotlin.
- `ExportedReceiver`: специальный вход управления Helper через ADB — только для лабораторной сборки; это не интерфейс производственного приложения.
- `DataExtractionRules`: allowBackup=false задан; отдельная политика переноса данных между физическими устройствами не исследуется. AVD всегда создаётся чистым.

Ни предупреждения, ни debug-режим не скрываются. Защищённость этих учебных APK как готового пользовательского продукта не заявляется.

## Практические ограничения

- Версия API фиксирована, но revision SDK-образа/emulator у провайдера может измениться; fingerprint и сведения SDK сохраняются в каждом запуске.
- Изолированные CI-группы используют разные одноразовые подписи и CA. Смешивание APK между ними нарушит контрольные условия.
- Лабораторные сертификаты действуют 7 суток; для новой локальной серии надо заново создать fixtures и пересобрать APK.
- Системный PIN-экран может сам запрещать скриншот. Не создаётся нарисованная замена; используются реальные доступные API/UI-свидетельства.
- Секретные тестовые данные и расшифрованная запись видны в журнале по замыслу опыта. Реальные пользовательские данные вводить не следует.
- Нет исследований аппаратной TEE/StrongBox, извлечения диска, Verified Boot или устойчивости к модифицированной привилегированной ОС.
